# 2026.295.1338 — fix(settings): accept engine.run=containerd and reject the retired nerdctl word

## Summary

Consumer leg of the engine-word cutover. `opencharly/spec v0.2026295.1243`
(spec#266) deleted `nerdctl` from `#EngineName` — the vocabulary is now
`podman | docker | containerd`, and `nerdctl` survives only as the CLI **binary**
named by `#EngineBinaries`. This repo still pinned `spec v0.2026287.1848`, so
`engine.run` had the contract exactly backwards: it rejected `containerd` and
accepted the retired `nerdctl`.

- **Pins.** `sdk` → `v0.2026294.1520`, `spec` → `v0.2026295.1243` — the same
  consumer pins `opencharly/plugin-nerdctl v2026.295.1321` landed. The
  `go 1.26.8` directive and the transitive upgrades follow the sdk's own
  declaration (identical to the sibling leg's `go.mod`).
- **One vocabulary source.** The `engine.run` rejection now reads
  `container.EngineNames()` (the CUE-generated `spec.EngineNames`) plus the
  `auto` resolution selector. The old arm called `kit.ValidateEngine` and then
  **discarded its error**, emitting a hardcoded `auto | docker | podman` list;
  that literal is gone.
- **Both test arms pinned.** `config_test.go` now asserts `containerd` is
  accepted *and persisted*, and `nerdctl` is rejected; it also asserts the
  message names the current vocabulary (`auto` + every `spec.EngineNames`
  member) and that `nerdctl` appears only as the rejected value. The vocabulary
  expected by the test is read from the same spec accessor, not transcribed.
- **R4 fix found on the same surface.** `README.md` documented
  `charly settings set engine.podman`, a key that does not exist; it now
  documents `charly settings set engine.run podman`, which was executed live.
- **R5 sweep.** No `nerdctl`-as-engine-word occurrence remains in this repo
  outside the negative test and its comment.
