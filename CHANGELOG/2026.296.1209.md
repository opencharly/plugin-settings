# 2026.296.1209 — feat(settings): add containerd.namespace and source the vocabularies from spec

## Summary

Adds the `containerd.namespace` settings key and sources the engine/backend vocabularies from the contract module (spec `v0.2026296.1036`, sdk `v0.2026296.1058`).

- `containerd.namespace` is accepted, persisted, validated and reported by `charly settings get/set/list/reset`. Default: the engine capability's namespace fact (`default`). A per-deploy `namespace:` still wins over the setting; the setting wins over the capability default. There is no env mirror (spec's resolution table has none).
- `engine.rootful` now validates against `spec.RootfulModes`, and the test pins every member — including the documented default `auto` — plus the contract's joined rejection list. `auto` is a member of the rootful vocabulary (unlike `vm.backend`'s selector), so no carve-out is required; the live probe exercises all four modes.
- `vm.backend` now validates against `spec.VmBackends`. This fixes a live defect on the same surface: the old literal list rejects `krun`, which the schema already carries.
- The valid-key vocabulary is stated once. The three verbs carried drifting copies (one omitted `hosts.<alias>`, another `keyring_collection_label`), and the CLI `get` surface advertised a fourth answer. A new consistency test ties the advertised hint to the implementation — and found a real pre-existing defect: `keyring_collection_label` was advertised and persisted but absent from the validation switch, so `settings set` rejected it. The case is restored.
- `go.mod`/`go.sum`: spec `v0.2026295.1243` → `v0.2026296.1036`, sdk `v0.2026294.1520` → `v0.2026296.1058`.
- Docs: the in-repo `settings` skill documents the key and its chain; the README's stale "no skill entity, tracked in #291" note is replaced (that issue is closed and the skill now lives beside the command — the `settings-skill` entity is at `candy/plugin-settings/charly.yml:62-66`).

No schema field was needed: the plugin's self-contained CUE schema describes the command contract and generates no `params` package, so there is no `cue-gen` artifact for this key surface.
